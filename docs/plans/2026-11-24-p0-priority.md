# P0: a priority for what must happen right away

Issue: #75 (Julius, 24 Nov: "add P0 that is only for ultra important things that needs to be
done asap").

## Behavior

Priority 0, shown as P0, above P1. Stored as the integer 0 in the same `priority` column (4 stays
"no priority"), so lower still means more urgent and every existing sort (`byPriority`) puts P0
first with no change.

Everywhere a priority is chosen or shown: task details (Mac toggle group and phone picker), the
long-press menu, the Board/Timeline filter, `p0` typed in New Task (read and marked like p1–p4),
the priority dot and the check circle's colour, and the MCP tools (schema 0–4, description).

## Decisions

- **Colour:** P0 is a deeper red than P1 with a stronger fill, so it stands out from P1 at a
  glance. Julius owns design; easy to change in `index.css` (`--priority-0`).
- **Older apps:** an app from before this reads a P0 task fine (the value is an integer) but
  shows no name for it until updated; the core of an old app refuses to *save* P0 (its check
  is 1–4). Acceptable: apps update themselves within a day.
- **No server change:** the hosted database has no check on the value.

## Verification

Core test that 0 is accepted and 5 refused; quick-add parsing tests for p0; tsc and vitest;
`cargo test -p done-core -p done-mcp`.
