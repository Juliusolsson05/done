# The address follows where you are

Issue #127. The owner: "add full route navigation to navigate between all open
tasks etc and different views in the route itself; refreshing takes me to the
homepage."

## What is there today (evidence)

- Where you are is `ui.view` (a `View`, `ui/src/lib/tasks.ts`) plus
  `ui.editing` (the open task) in `App.tsx`'s state. `app-context.ts` says it
  outright: "Not saved: a reload always starts in Today."
- The phone's way back is `ui.history`, a stack kept by `lib/view-history.ts`
  (`opened`, `back`): a tab starts over, moving within one kind replaces.
  The header Back (`phone.tsx` `PhoneHeader`) and the edge swipe
  (`useEdgeSwipeBack`) both call `app.back()`. The browser's Back is not
  connected to any of it: it leaves the app.
- The open note is Notes' own state (`openId` in `notes.tsx`); `view.id` is
  only a request from search or a note link ("asked"). Read mode, the folder
  and the phone's "at folders" are Notes' state too.
- Settings opens a workspace's page from its own state (`space` in
  `settings.tsx`).
- Scope (personal / a workspace / All) is `scope-store.ts`, remembered per
  device in localStorage; `app.setScope` resets a project view to Today.
- Nothing reads or writes the address in the app. `location` is used only for
  `reload()` (midnight, sign-in, sign-out, a 401) and `?signin=failed` on the
  sign-in screen. `done:task/<id>` and `done:note/<id>` in notes are handled by
  the Notes page itself (`openView({kind:'notes', id})`, mentions); `done://auth`
  is the apps' sign-in callback (`cloud.ts`), unrelated to pages.
- The server (`crates/server/src/main.rs`) answers `/` with the app (cloud: by
  host; `hi.thedone.app` gets the feedback landing) and 404s every other
  unknown path. Sign-in's `then` (`auth.rs` `back_to`) allows only
  `/feedback`, `/oauth/authorize?...` and `/invite/<token>`.
- Tauri 2.12.5 (`tauri/src/manager/mod.rs` `get_asset`): a path with no asset
  falls back to `<path>.html`, `<path>/index.html`, then `index.html`. The UI
  is one self-contained `index.html` (vite-plugin-singlefile), so any path
  loads the whole app in the Mac, Windows, iPhone and iPad web views.

## Decisions

- **Paths, everywhere, with the History API.** The web server learns the app's
  paths from an explicit table; the apps need nothing (Tauri serves
  `index.html` for any path, checked in its source above), and the paths work
  offline because nothing is asked of a server. Ruling: no hash routes and no
  in-memory router in the apps — why: one scheme, and reload in the apps
  already works — cost if wrong: a web view that does not fall back would show
  a blank page on reload; the fix is a hash in the apps only, inside
  `lib/router.ts`.
- **The table** (`ui/src/lib/route.ts`, mirrored in
  `crates/server/src/routes.rs`):

  | Path | Where |
  | --- | --- |
  | `/`, `/today` | Today (`/` is rewritten to `/today`) |
  | `/inbox`, `/upcoming`, `/assigned` | Inbox, Upcoming, Assigned to me |
  | `/timeline`, `/board` | Timeline, Board |
  | `/focus`, `/time-sheet`, `/completed` | Focus, Time sheet, Completed |
  | `/notes`, `/notes/<id>` | Notes, one note |
  | `/project/<id>` | a project's list |
  | `/settings`, `/settings/workspace/<id>` | Settings, a workspace's page |
  | `/lists`, `/notifications` | the phone's Lists and notifications |
  | any of these `?task=<id>` | that task open over the view |

  Ids are digits only (at most 20, a safe integer). Nothing else goes in the
  address: no titles, emails or tokens. Filters, zoom, scroll, the Timeline's
  start, popovers, read mode, the notes folder and search stay out.
- **Server fallback:** an axum `fallback` that answers GET with the app shell
  only when the path is in the table, else 404 as before. A fallback runs only
  when no route matched, so it cannot shadow a route that exists now or is
  added later; the table keeps it from answering anything else. On
  `hi.thedone.app` app paths still 404 (the landing host answers as before).
  The same fallback in the local server (it is behind `local_only` already).
- **Sign-in comes back:** the sign-in button sends `then=<path?task=id>` and
  `back_to` also allows a path the table accepts, with a query of at most
  `task=<digits>`: always a local path, never `//`, `\`, a scheme or a new line.
- **Scope is not in the address.** A project, task or note link names an id,
  and the id decides the space: if it is in another space you are in, the
  picker moves there. A view without an id (Today, Board) keeps the device's
  remembered scope. Ruling — why: ids are global and the server already
  decides spaces; a `?space=` would be one more id to validate and keep in
  step — cost if wrong: a shared `/board` opens in the reader's own scope.
- **Not there, or not yours:** a link to a task, project or note that this
  account cannot see (deleted, or in a workspace you are not in) lands on Today
  (Notes for a note) and says "You don't have access to this, or it was
  deleted." The two cases are one message on purpose: telling them apart would
  confirm to a non-member that the id exists. Nothing is shown of it, since the
  app only holds what the server sent. An unknown path lands on Today and the
  address is put right (no 404 page inside the app).
- **History:** a view change pushes an entry. Opening a task, a note from the
  Notes list on a phone or a narrow window, or a workspace page in Settings
  pushes an entry marked "over" the one under it; closing it goes `history.back()`,
  so Back closes it and Forward reopens it, and closing never leaves a
  duplicate behind. Leaving an over entry for somewhere else replaces it.
  Notes opened automatically (the newest note on a wide screen, the first
  search match) replace. Back never traps: with nothing of the app's behind
  it, the phone's Back replaces with Lists instead of leaving the app.
- **The phone's stack is the browser's history.** Each entry remembers the
  address it was pushed from (`history.state.prev`). The header Back, the
  edge swipe and the browser Back all become `history.back()`, and the back
  label reads that previous entry. `lib/view-history.ts` (the separate stack)
  is removed. Ruling — why: two stacks disagree as soon as one is walked
  without the other — cost if wrong: Back from a list opened from another list
  (via search) now goes to that list rather than skipping it, which is what a
  browser does.
- **Titles** name the view only: "Today · done", "Project · done",
  "Note · done". Never a task title, project name or note title, so browser
  history on a shared computer does not list what someone works on.
- **Kept as is:** keys 1–9, Cmd/Ctrl+K, note links (they call `openView`,
  which now also pushes), the sign-in callback, the midnight and sign-out
  reloads (a reload keeps the address), a Focus reminder showing after a
  reload (it wins over the address, as before), the Mac menu bar's commands
  (focus only; none navigate). Every change to tasks still goes through
  `change()`; routing never changes data.
- **Scroll on Back:** left to the browser and to #119's per-page memory; not
  fought here.

## Build order

1. `lib/route.ts`: `parseRoute`, `formatRoute`, `titleOf`, `stepTo` (push,
   replace, back or nothing), pure, with tests.
2. `lib/router.ts`: the History API behind a small interface, tested against a
   fake history (Back does not loop or leave).
3. Rebase on the newest `origin/main`, then wire it into `App.tsx`,
   `phone.tsx`, `notes.tsx`, `settings.tsx`, `sign-in.tsx`.
4. Server: `routes.rs`, the fallback, `back_to`; tests.
5. `ui/checks/routes.cjs`, failing on main.

## Tests

- `route.test.ts`: every route round-trips; junk (unknown path, missing id,
  letters, negative, too long, extra segments, encoded characters, `//`,
  trailing slash, junk `task`) is read as documented.
- `router.test.ts`: push, replace, over and back; closing an over entry goes
  back; Back with nothing behind it replaces instead of leaving.
- Server: app paths answer the shell, junk 404s, `/api`, `/auth`, `/privacy`,
  `/support`, `/feedback`, `/healthz` and the landing host answer as before;
  no registered route path is in the table; `back_to` takes app paths and
  refuses unsafe ones.
- `ui/checks/routes.cjs` (Playwright): refresh on `/upcoming` stays on
  Upcoming; Back from an open task returns to its view with the task closed.

## Rulings made while building

- Ruling: the task link form is `?task=<id>` on the view it was opened from;
  no separate `/task/<id>` — why: one form, and the view under it is what
  Back returns to — cost if wrong: a shared link opens over the sharer's view;
  when the task is not listed there (a window edits a task in its row), its
  own list takes the place (Inbox or its project), so it still opens.
- Ruling: `history.scrollRestoration = 'manual'`, and #119's scroll memory
  keeps its positions in the browser's history entries (`router.keepScroll`)
  instead of a depth-keyed map — why: with Back now a real `popstate`, the
  browser restored the pushed page's 0 over #119's saved position
  (touch-sizes.cjs failed: "Back returned Lists at scrollY 0, not 300") — cost
  if wrong: none seen; the window layout scrolls inside the page, not the
  window, so the browser's own restoration never applied there.
- Ruling: the Notes page acts only on a new ask from the address, and tells
  the app about a note only when the open note changes — why: acting on every
  change of the notes reopened the deleted note's neighbour over Undo
  (notes-header-menu.cjs) — cost if wrong: none seen.
- Ruling: a flag for "the next step replaces" is only set when the step
  happens — why: a flag left set turned the next key press into a replace,
  so Back skipped a view (found in the browser run, V /notes).

## Not verified

- The Mac, Windows, iPhone and iPad apps were not built (no tauri or xcode
  builds in this change). Reload on an app path rests on Tauri 2.12.5's
  `get_asset` falling back to `index.html` (read in its source) and on the UI
  being one file. The first thing to check on a device: open a list, pull to
  reload (or Cmd+R on the Mac), and see the same list.
- iOS's own edge swipe in WKWebView (`allowsBackForwardNavigationGestures`)
  is off in Tauri by default; the app's swipe goes through `history.back()`
  and was checked in Chrome with touch only.
- `notes-header-menu.cjs` (4 controls: #119's Show sidebar) and
  `board-heights.cjs` (844x390 columns) fail on main as well; not touched here.
