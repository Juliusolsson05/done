# Rebuild the interface in React, Tailwind and shadcn/ui

Issue: #1

## What changes

`ui/index.html` (one file, hand-written CSS and JavaScript) becomes a Vite project in `ui/`: React, TypeScript, Tailwind and shadcn/ui components. What the app does stays the same.

## Rules

- Controls and surfaces are shadcn/ui components. Where shadcn has none (the timeline grid), the view is laid out with plain elements and theme utilities, and its controls are still shadcn components.
- No one-off Tailwind values (no `w-[244px]`, no `text-[13px]`, no hex colours in class names). The look is defined once as theme tokens in `ui/src/index.css`; components use those tokens and Tailwind's standard scale.
- Positions that are computed from data (where a timeline bar sits, a project's colour) are set with a `style` prop. They are data, not design.

## Decisions

- **One built file.** The build inlines scripts and styles into `ui/dist/index.html`, so the web server keeps embedding a single file and the desktop app points at `ui/dist`.
- **The backend contract does not change.** The interface still calls `state`, `sync`, `info` and `restart` in the desktop app, or `/api/state` and `/api/sync` in the browser.
- **Pure logic moves to tested modules:** reading a typed line, day arithmetic, view grouping, and working out what changed since the last save.
- **The theme carries the look already agreed:** light only, neutral surfaces, one blue for actions and today, colour otherwise only for priority, overdue and projects.

## Steps

1. Scaffold the Vite project with Tailwind and shadcn/ui; write the theme.
2. Port the logic modules with tests.
3. Build the views from shadcn components.
4. Point the desktop app, the web server, CI and the release workflow at the built interface.
5. Check every view and action in a browser against the current behaviour.
