# Quick notes: a Notes page for jotting things down

Fixes #27.

Status: built; waiting for the owner to look at the local preview before merging.

## Outcome

A **Notes** page in the sidebar. Press **New note**, type, and it is saved by itself. The use case from the owner: in the middle of a chat with a co-founder, write down the five funds you want for the seed round, without opening Apple Notes. Notes are plain text; the first line is the title in the list; the newest-changed note is on top; Delete has Undo.

Kept deliberately small (the owner: "this should not be bloat"): no folders, formatting, pinning, search, links to tasks, or agent (MCP) tools.

## Design

Rulings (owner said build it; defaults taken, no question left open):
- Ruling: notes have their own table and calls, not `sync(Change)` — typing a note must never make a task save fail as stale — cost if wrong: two devices editing one note at once keep the later save.
- Ruling: plain always-editable text; links are not clickable here — a click in a text box is for typing — cost if wrong: copy a link out by hand.
- Ruling: saved 500 ms after typing stops, and when leaving the note or page — cost if wrong: at most the last half second is lost if the app is killed mid-word.
- Ruling: an empty note is deleted when you leave it, so New note pressed by mistake leaves nothing behind.

### Core (`crates/core/src/lib.rs`)

- `Note { id: i64, text: String, updated_at: i64 }` (ms since 1970, camelCase over JSON).
- Table `note` created with `CREATE TABLE IF NOT EXISTS` in `Store::open`.
- `Store::notes() -> Vec<Note>`, newest `updated_at` first.
- `Store::save_note(id: Option<i64>, text: String, updated_at: i64) -> Note` — no id makes a new note; with an id it is written (insert or replace, so Undo of a delete puts the same note back). Never touches `rev`.
- `Store::delete_note(id)`.

### Apps

- Tauri commands `notes`, `save_note`, `delete_note`.
- Web, local and hosted: `GET /api/notes`, `POST /api/notes` (JSON `{ id?, text, updatedAt }`), `POST /api/notes/delete` (JSON `{ id }`).

### Interface

- `ui/src/lib/notes.ts` — `Note` type, `titleOf(text)` (first non-blank line, or "New note"), `whenText(updatedAt, now)`.
- `ui/src/lib/backend.ts` — `loadNotes`, `saveNote`, `deleteNote`.
- `ui/src/components/notes.tsx` — the page: header with New note; list (title, when) beside the open note's textarea; on a phone the list, and a tapped note full width with Back.
- `tasks.ts` view kind `notes`; `App.tsx` renders it (quick add from it goes to Inbox); sidebar item with key 8.

## Tests

- Core: a saved note comes back; saving with its id changes it and moves it to the top; a deleted note is gone and saving it again with its id brings it back; saving never moves the tasks revision.
- Interface: `titleOf` takes the first non-blank line and trims it; an empty note is "New note".
